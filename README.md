# 🧶 编织行指令审校（Knit Row Review）

一个用于校验编织逐行针数指令的 Web 应用：填写起始针数和逐行指令后，系统解析并展开每行，以上一行产出作为下一行的可用针数，逐行显示 **消耗 / 产出 / 剩余**；针数不匹配时**定位第一个无法执行的源指令**，并给出**短缺**或**未消耗**数量。编辑任一行后实时重算全部后续行，方案可导入 / 导出为 JSON。还可把当前方案**保存为浏览器本地基线**，继续编辑后与基线做**方案对照**（行对齐差异表 + 首个分歧定位）。另有**尺码联检**：为同一份行指令录入 2～8 个命名尺码及各自起始针数，一键生成行×尺码矩阵，对比各尺码逐行状态并定位首个尺码分化行。

- 后端：Python 3.11 + FastAPI（解析、展开、逐行审校引擎）
- 前端：原生 HTML / CSS / JavaScript（无构建、无前端框架）
- 部署：Dockerfile + Docker Compose，依赖安装与启动初始化都在容器启动流程中完成

## 语法规则

指令之间可用任意空白分隔（空白会被忽略），数字必须为正整数。

| 指令 | 含义 | 消耗 | 产出 |
| --- | --- | --- | --- |
| `kN` | 平针：编织 N 针 | N | N |
| `incN` | 加针：1 针放出 N 针 | 1 | N |
| `decN` | 减针：N 针并为 1 针 | N | 1 |
| `[指令序列]*M` | 将方括号内序列整体重复 M 次，**可嵌套** | 序列合计 × M | 序列合计 × M |
| `[指令序列]*~N` | **自适应重复**：按顺序重复序列，直到本行恰好剩余 N 针供后续指令使用（N 为非负整数） | 展开前推导 | 展开前推导 |

示例（起始 20 针）：

```text
[k2 inc1]*4 k8      # 耗 20 产 20
[k3 dec2]*4         # 耗 20 产 16
k16                 # 耗 16 产 16
[k3 inc2]*4         # 耗 16 产 20
[k2]*~4 k4          # 自适应：(20-4)/2 = 8 轮，留 4 针给 k4，耗 20 产 20
```

嵌套示例：`[[k2]*2 inc1]*3` 表示 `(k2 k2 inc1)` 重复 3 次。

### 自适应重复 `[...]*~N`

- 引擎在**展开之前**按本行当前剩余针数推导实际重复次数 M：设序列每轮消耗 `c` 针，则 `M = (当前剩余 − N) / c`，必须整除，且结果为非负整数（M 可以为 **0**，即该块一次也不执行）。
- 推导在运算符 `*` 位置完成：`当前剩余 < N`（无法保留）或 `(当前剩余 − N)` 不能被 `c` 整除时，在该位置返回明确错误，本行不产出并**阻断后续行**。
- 自适应块只能出现在**行内顶层**；一行可有多个，按顺序各自依据当时的剩余针数推导。块内部可以嵌套**固定次数**块（如 `[[k2]*2 inc1]*~5`），但不允许再嵌套自适应块。
- 推导结果会在 API 中逐块返回（实际重复次数、每轮消耗/产出、源文本区间），前端在源指令旁展示「实际重复 M 次」徽标。
- 例：起始 20 针时 `[k2]*~4 k4` 推导为重复 8 次（消耗 16、留 4 针），随后的 `k4` 正好用完；若写成 `[k2]*~5`，因 `20-5=15` 不能被 2 整除而报错。


### 审校语义

- **每行可用针数 = 上一行产出**（第 1 行为填写的起始针数）。
- 展开行内指令并按顺序模拟执行；某条指令需要的针数超过当前剩余针数时：
  - 状态为「针数短缺」，在源文本中**高亮第一个无法执行的指令**；
  - 返回该指令位置（列区间）、`需要 N 针 / 仅剩 M 针 / 短缺 N-M 针`；
  - 该行不产生产出，**后续行标记为「已阻断」**（可用针数无法确定）。
- 一行指令全部可执行但**没有把可用针数用完**时：状态为「未全部消耗」，给出未消耗数量（该行仍正常产出，不阻断后续行）。
- 自适应块 `[...]*~N` 在展开前先做可行性推导：无法整除或保留目标不可达时，在 `*` 运算符位置报错并阻断后续行；推导成功后实际重复次数回填，再参与展开与模拟。
- **针数变化来源**：通过 / 未全部消耗的行会附带一份清单，按源文本中每处 `incN` / `decN` 的区间汇总**实际执行次数、消耗针数、产出针数与净变化**：
  - 固定重复块嵌套时执行次数逐层相乘（如 `[[inc2]*2]*3` 中 `inc2` 执行 6 次）；自适应块使用本行推导出的实际重复次数；
  - 同一源区间的多次执行合并为一条；字面相同但位置不同的指令分列；
  - 每行显示净变化合计，并与该行「产出 − 消耗」核对；
  - 针数短缺、语法错误与已阻断的行不生成清单。
- 语法错误（未闭合的方括号、缺少数字、重复次数为 0、自适应块嵌套等）会在出错列标出 `▲` 并阻断后续行。
- 单条方案展开后的叶子指令上限为 100,000 条，防止超大重复次数导致的资源问题；界面上超过 200 条时只预览前 200 条并注明总数。

## 界面功能

- 左侧：起始针数、逐行指令编辑（添加 / 删除 / 上移 / 下移）、语法帮助；编辑后 250 ms 防抖自动重算，内容自动保存到浏览器 `localStorage`。
- 右侧：汇总徽标（通过 / 未耗尽 / 短缺 / 语法错误 / 阻断数量与最终针数）与逐行卡片，含行之间的「上一行产出 → 本行可用」流向、消耗 / 产出 / 剩余指标、错误高亮、展开指令列表。
- 逐行卡片内含「针数变化来源」表格（通过 / 未全部消耗的行）：每处 `incN` / `decN` 一行，列出执行次数、消耗 / 产出针数、净变化，表尾为合计；**点击条目会在源指令文本中高亮定位该指令**（再次点击取消）。
- 编辑区下方「方案对照」栏：**保存当前为基线** / **清除基线**，并显示已存基线的起始针数、行数与保存时间。
- 页面底部「方案对照」面板（保存基线后出现）：基线 ↔ 当前的行对齐差异表，随编辑实时刷新。
- 页面底部「尺码联检」面板：录入 2～8 个命名尺码及各自起始针数，点击「开始联检」生成行×尺码矩阵；尺码列表自动保存到浏览器 `localStorage`。
- 顶部：**载入示例**、**导入 JSON**、**导出 JSON**。

### 方案对照（基线 diff）

1. **保存基线**：点击编辑区下方的「保存当前为基线」，当前起始针数与全部行文本即存入浏览器 `localStorage`（不影响方案本身的自动保存）；基线存在时按钮变为「更新基线为当前」，再次点击即覆盖。
2. **继续编辑**：照常增删改行、调整起始针数，底部对照面板随每次重算实时刷新。
3. **查看差异**：对照表按行对齐展示两版的**行号、文本、状态与行末针数**，变更类型分为 未变 / 修改 / 新增 / 删除。
4. **清除基线**：点击「清除基线」移除本地基线并收起对照面板。

对照规则：

- **对齐**：按原始行文本（精确相等）做稳定的最长公共子序列（LCS）对齐；重复出现的相同文本总是取**最靠前的可行配对**。
- **修改 / 新增 / 删除**：未配对区段内，基线侧与当前侧的行按顺序**成对标记为「修改」**，剩余行分别标记为「删除」（仅基线有）或「新增」（仅当前有）。
- **两版分别审校**：基线与当前各自调用 `POST /api/analyze`，两侧结果独立渲染——一侧出现语法错误 / 短缺 / 阻断（甚至请求失败）时，另一侧的后续行结果仍完整展示，失败侧标注「分析失败」。
- **首个分歧**：从表头向下，第一个**双方都有行**（未变或修改）且**状态或行末针数不同**的位置以 `⚑ 首个分歧` 标出并高亮；新增 / 删除等缺席行不参与该判定。行末针数仅「通过 / 未全部消耗」的行有确定值，其余状态显示 `—`。
- 起始针数不同时会在对照汇总中单独提示（它会使所有行的可用针数不同）。

对照功能纯前端实现，无需额外服务；按上文「一条命令启动」后访问 **http://localhost:8000**（端口由 `HOST_PORT` 控制，默认 8000）即可使用。

### 尺码联检

**入口**：页面底部「尺码联检」面板（与方案对照面板并列）。按上文「一条命令启动」后访问 **http://localhost:8000**（容器内固定端口 8000，宿主机端口由 `HOST_PORT` 控制，默认 8000）即可使用。

1. **录入尺码**：为当前这份行指令录入 2～8 个命名尺码，每个尺码有独立的起始针数；可添加 / 删除尺码（少于 2 个不可再删，多于 8 个不可再加）。尺码名称不能为空且不能重复。尺码列表自动保存到浏览器 `localStorage`，刷新页面后保留。
2. **开始联检**：点击「开始联检」，后端对每个尺码**独立执行**与单方案完全相同的解析、自适应重复推导与跨行针数传递（`POST /api/sizes/analyze`），随后页面展示**行×尺码矩阵**。
3. **查看矩阵**：每格显示该尺码在该行的**状态、可用针数与行末针数**（已阻断的行显示 `—`）。某尺码出现针数短缺或语法错误时，**只阻断该尺码的后续行**，其他尺码继续审校。
4. **首个尺码分化行**：同一行中，未被阻断的尺码出现两种及以上不同状态时，该行为尺码分化行；矩阵以 `⚑ 首个分化` 标出**第一个**这样的行并高亮。**仅比较状态**——起始针数不同造成的行末针数差异本身不算分化；已阻断的尺码不参与该行的判定。
5. **定位与详情**：点击任意单元格，左侧编辑区对应源行会闪烁定位，矩阵下方同时显示该尺码在该行的完整审校卡片（源文本错误高亮、消耗 / 产出指标、错误信息、针数变化来源等）。
6. **过期提示**：联检之后若继续修改行指令、起始针数或尺码，矩阵会标记为「已过期」（半透明），重新点击「开始联检」即可刷新。

联检结果基于各尺码独立的逐行审校结果，与单方案审校、基线对照、JSON 导入导出互不影响，可同时在同一页面使用。

### 方案 JSON 格式

```json
{
  "format": "knit-row-review/v1",
  "name": "编织方案",
  "start_stitches": 20,
  "rows": ["[k2 inc1]*4 k8", "[k3 dec2]*4", "k16", "[k3 inc2]*4", "[k2]*~4 k4"],
  "exported_at": "2026-09-20T00:00:00.000Z"
}
```

导入时只需包含 `start_stitches`（非负整数）和 `rows`（字符串数组）；其余字段可省略。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/analyze` | 提交方案，返回逐行审校结果 |
| `POST` | `/api/sizes/analyze` | 尺码联检：同一份行指令按 2～8 个尺码各自起始针数独立审校 |
| `GET` | `/api/health` | 健康检查，返回 `{"status":"ok"}` |
| `GET` | `/` | 前端页面 |

请求：

```bash
curl -s -X POST http://localhost:8000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"start_stitches": 6, "rows": ["k2 inc1 dec4"]}'
```

短缺响应（节选）：

```json
{
  "status": "shortage",
  "available": 6,
  "consumed": 3,
  "failing_instruction": "dec4",
  "failing_start": 8,
  "failing_end": 12,
  "shortage": 1,
  "error": "针数不足：执行 dec4 时需要 4 针，本行剩余可用仅 3 针，短缺 1 针"
}
```

自适应重复响应（节选）：每个成功推导的自适应块返回实际重复次数与源文本区间，前端据此在源指令旁展示「实际重复 M 次」：

```bash
curl -s -X POST http://localhost:8000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"start_stitches": 20, "rows": ["[k2]*~4 k4"]}'
```

```json
{
  "status": "ok",
  "available": 20,
  "consumed": 20,
  "produced": 20,
  "remaining": 20,
  "expanded_count": 9,
  "adaptive_blocks": [
    {
      "start": 0,
      "end": 7,
      "star_pos": 4,
      "target_remaining": 4,
      "actual_repeats": 8,
      "per_pass_consumed": 2,
      "per_pass_produced": 2
    }
  ]
}
```

无法整除（如 20 针执行 `[k2]*~5`）时返回 `"status": "error"`，`error_pos` 指向 `*`（此处为列 4），错误信息说明剩余针数、目标保留针数、每轮消耗与不可整除关系，后续行为 `"blocked"`。

针数变化来源响应（节选）：通过 / 未全部消耗的行返回 `stitch_changes` 清单与净变化合计 `stitch_net`（`stitch_net` 恒等于该行 `produced - consumed`，前端据此核对）；短缺 / 语法错误 / 阻断行返回空清单且 `stitch_net` 为 `null`：

```bash
curl -s -X POST http://localhost:8000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"start_stitches": 10, "rows": ["[inc2]*~4 k4"]}'
```

```json
{
  "status": "ok",
  "consumed": 10,
  "produced": 16,
  "stitch_net": 6,
  "stitch_changes": [
    {
      "start": 1,
      "end": 5,
      "instruction": "inc2",
      "executions": 6,
      "consumed": 6,
      "produced": 12,
      "net": 6
    }
  ]
}
```

`stitch_changes` 中每个条目对应源文本中一处 `incN` / `decN` 指令（`start` / `end` 为 0 基列区间，前端点击条目即按此区间定位原文）：`executions` 为实际执行次数（固定块逐层相乘、自适应块取推导次数），`consumed` / `produced` 为该区间的合计消耗 / 产出针数，`net` 为净变化（`produced - consumed`）。同一区间的多次执行已合并；字面相同但区间不同的指令分列。

尺码联检请求 / 响应（节选）：每个尺码独立返回一份与 `/api/analyze` 相同结构的逐行结果，某尺码的短缺 / 语法错误只阻断该尺码自己的后续行：

```bash
curl -s -X POST http://localhost:8000/api/sizes/analyze \
  -H 'Content-Type: application/json' \
  -d '{"sizes": [{"name": "S", "start_stitches": 4}, {"name": "M", "start_stitches": 10}],
       "rows": ["dec5", "k1"]}'
```

```json
{
  "sizes": [
    { "name": "S", "start_stitches": 4,
      "rows": [ {"status": "shortage", "shortage": 1, ...}, {"status": "blocked", ...} ] },
    { "name": "M", "start_stitches": 10,
      "rows": [ {"status": "unconsumed", "remaining": 1, ...}, {"status": "ok", ...} ] }
  ]
}
```

尺码数量须为 2～8 个，名称非空白且不重复，起始针数为非负整数，否则返回 422。

## 本地开发（不使用 Docker）

```bash
pip install -r requirements-dev.txt        # 含 pytest / httpx
uvicorn app.main:app --reload --port 8000  # http://localhost:8000
pytest -q                                   # 运行测试（63 个用例）
node tests/test_compare.js                  # 方案对照（LCS 对齐 / 首个分歧）纯逻辑测试
node tests/test_sizes.js                    # 尺码联检（首个尺码分化行）纯逻辑测试
```

app/

  static/
    index.html        # 页面结构
    style.css         # 样式
    compare.js        # 方案对照纯逻辑：LCS 行对齐、行末针数、首个分歧定位（无 DOM 依赖）
    sizes.js          # 尺码联检纯逻辑：首个尺码分化行定位（无 DOM 依赖）
    app.js            # 编辑器、防抖重算、结果渲染（含针数变化来源表格与点击定位）、
                      # 基线保存 / 清除、双版独立审校与对照表渲染、JSON 导入导出、
                      # 尺码编辑（本地保存）、联检矩阵渲染与单元格定位详情

Dockerfile            # 镜像构建（构建时安装依赖）
docker-entrypoint.sh  # 容器启动初始化自检
docker-compose.yml    # 单服务编排 + 健康检查
